# Targeted acceptance checks

This is the implementation plan requested for the Full scan's P6–P20 proposals. The labels refer to that report, not test selectors or a second ledger. Plans and automated checks do not establish human sign-off. Unexecuted protection remains open.

The review used Claude Sonnet 5.5 with High effort and verified returned model metadata. The decisions below also account for the actual source and existing suites. Prefer small deterministic regressions; keep expensive model checks opt-in and actual browser/client acceptance manual. No new framework, dependency, CI job or operational-state schema is proposed.

## Implemented checks

The original decision table below is retained as design rationale. Implementation now lives in `acceptance_support.rb`, `acceptance_cases.rb`, `git_acceptance.rb`, `smoke_acceptance.rb` and `browser_acceptance.py`, beside the existing smoke and docs checks.

Normalize, test-lifecycle and publication verification are callable functions in `acceptance_support.rb`. `test_acceptance_oracles.rb` exercises those actual checks directly with synthetic inputs and disposable Git repositories; it calls no models and runs with the existing offline suite.

Local normalize-to-ship discovery uses the packaged `normalize_handoff.py` locator I/O helper and shared handoff protocol. `test_normalize_handoff.py` checks independent-process lookup, retained runs, atomic no-clobber registration, unsafe paths/permissions, missing backups and worktree/clone boundaries. These checks do not certify a recovery map or authorize publication.

The `normalize-rewrite` fixture also uses a reviewed controller-owned backend wrapper to require the actual locator before filtering, then delegates to the installed backend. `history-auto-discovery` starts a fresh model session without a recovery path in its request and verifies the missing local-fixture publication; `history-missing-handoff` requires a pending result with unchanged refs and locator, without searching for the relocated backup. They use the existing opt-in model/sandbox limits; no real project record, backup or remote is used.

The `normalize-readiness-*` scenarios exercise the unanswered first gate, its complete plain-bullet notice, Review only with auto-commit enabled, reused Team ready followed by an unanswered final Apply, private/no-correction history and Stop. Hidden synthetic commit-body markers plus exposed-tool/state guards reject history review while readiness is pending. Consumer/package bytes and Git/index/config stay unchanged. `normalize-branches-*` uses a separate owned clone to push a new branch after the consumer's last remote update: fresh discovery must leave unapproved preparation pending or create only the exactly approved local branch and optional matching tracking ref, preserving the remote, current checkout, existing refs/config and worktree. The full rewrite fixture supplies both independent acknowledgements; readiness alone never substitutes for preparation, rewrite or publication approval.

`ship-ordinary-review` checks a one-commit feature source against an owned local bare remote, with None for targets and an unanswered push approval. It verifies exact consumer/Git/package/remote preservation, the actual source identity and no unrelated release/target/archive/history procedure loads. It reports transient elapsed time, exposed call counts and verified model usage; no runtime telemetry, benchmark mode or automatic model run is added. One pre-change/final Sonnet 5.5 High smoke pair observed 70.70s/17 tool calls versus 85.77s/16. This establishes no wall-time improvement or Codex performance guarantee: provider variance, generated output and partial reference reads differ. Use repeated controlled runs for latency claims. Ship's ordinary guidance shrank from 8,129 to 3,574 words; every substantive prior paragraph remains in the core or its selected release/target procedure, not discarded for speed.

- **P8/P9/P20:** actual Chrome checks cover both setup pages' clicks, keyboard/wrap/focus/ARIA, fragments, all twelve legacy redirects, JavaScript-disabled content and print preview; saved/invalid themes, cross-tab change/remove/clear, blocked-storage faults and DevTools system-theme changes; and rendered ship/test Mermaid SVG labels. The blocked-storage page injects a `SecurityError` before the real theme script; it changes no privacy setting. Browser controls were restored afterward. Browser version was not obtained because browser policy blocks `chrome://version`; these are scoped observations on the current Chrome/macOS host, not a browser support matrix or human usability sign-off.
- **P10:** complete exposed Claude tool/result/message traces, synthetic leak positive controls and a value-free env audit. Scanner controls cover raw/partial/JSON-escaped/base64/hex values, malformed/incomplete streams and wrong-model results. A separate owned read/write probe checks the configured OS sandbox boundary. No claim about hidden channels or every encoding.
- **P11/P12/P13:** disposable merge graphs, current-run message/metadata/ref oracles and independent bundle recovery; moved-remote and partial-publication scenarios; tampered-report and completed archive/ship-backup resumes. Publication fixtures use a controller-prepared actual `git-filter-repo` rewrite with independently verified objects and a synthetic upstream handoff, not this project's state. A reviewed local-bare `pre-receive` recorder independently checks actual updated refs. There are no real provider writes, deployments, services, LFS assets or recovery certifications.
- **P14/P15/P16/P17/P18:** source-only preview; failed/deferred/successful test lifecycle and actual code-before-closure provenance; renamed/nested source and loaded-package adoption guards, custom-copy Keep and writing-only adoption; exact partial log/README updates; complete fictional legal drafts left uncommitted even with auto-commit enabled; and release-proposal reasoning against the actual ship source. No duplicate SemVer parser or legal-validity claim.
- **P19:** current Codex desktop answers verified native Single, Input/custom text, Review/Revise, explicit None, and Multi through independent membership questions and full-list Input. The first Single card was reported invisible; its resolved reply was followed by working Input, and an explicitly requested later retry confirmed visible choices. Claude for Mac 3.6556.2 (20c019), Code with Sonnet 5.5 / High, passed native Single/Multi, custom Unicode input and Review/Revise in one batch. After reading the shared QM contract, it retained all nine choices through a native Other/Input alternative, distinguished submitted None from Skip, and left the skipped question unanswered. Pending preselected answers caused no submission, duplicate prompt or effects; fixture bytes and project Git state stayed exact. These are scoped current-host UI observations, with developer answers on Codex and operator-driven synthetic interactions on Claude, not authorization for real work or a client compatibility matrix. Codex self-inspection remains blocked and its client version was not obtained; its eligible generic question tools expose no Multi switch, so the verified alternatives cover that capability gap. The headless unanswered-question regression remains separate.

Run the offline regressions with the existing `bundle exec rake test` environment. They include `test_acceptance_support.rb` and `test_git_acceptance.rb` and call no models. For explicit live checks:

```sh
ruby scripts/smoke_acceptance.rb --list
ruby scripts/smoke_acceptance.rb env-confidentiality
python3 -I -B scripts/browser_acceptance.py
```

Each live invocation selects one Claude scenario, uses Sonnet 5.5 / High, a $1 API cap, a 240-second process-group timeout, strict Bash sandbox settings and a complete exposed stream with metadata validation. No automatic batch/model run is added to Rake or CI. The sandbox setup follows the [official Claude sandbox guidance](https://code.claude.com/docs/en/sandboxing); the model receives only Bash, with native file tools, MCP servers and client customizations disabled. Only the reviewed local-bare fixture recorder runs as a Git hook. Source is copied into a disposable complete package. Exact file preservation checks apply to the package and consumer fixtures; only newly created empty native `.claude/.cc-writes` directory pairs are treated as client bookkeeping. Fixture records, model traces and recovery data never come from this project's operational files. These live observations are Claude-only; offline Codex stream fixtures do not certify Codex workflow behavior.

The browser command serves the already-built `_site` on a fresh loopback port with visible, isolated fault controls. Stop it with Ctrl-C. It installs nothing and writes no site settings or source files.

## Model-check boundaries

The shared support is implemented and opt-in. Keep any additional scenarios within these boundaries rather than turning the plans into an automatic model matrix.

1. Create a fresh temporary consumer repo outside Helm source/install roots. Use fictional identities, synthetic records and generated canaries only. Reuse `HelmSmoke.environment`, no-follow artifact reads and exact file/index/ref snapshots. Do not read this project's operational state, history-rewrite proof or archive bundles to construct fixtures.
2. Review the actual CLI, model, tool/permission settings, selected scenario, allowed paths/refs and backend before execution. For Claude use the project-required Sonnet 5.5 / High and verify metadata. For Codex explicitly select the intended available model/effort. One scenario/client per invocation, at most 240 seconds and eight model turns where enforceable; agree an enforceable spend limit before a paid run. Do not change the user's global client configuration or repurpose `HOME` to bypass authentication/policy.
3. Prove execution isolation before allowing writes: temp paths/local remotes only, no production credentials, hooks, services, real provider endpoints or publication. A prompt saying "no network" is not enforcement. Use available sandbox/tool restrictions and a reviewed local provider adapter; if they cannot exclude unintended targets, leave execution pending.
4. Put concrete fixture-only approvals in the request. Interactive approval unavailable means stop at that gate, not invent an answer. For later turns pass only the specific approved action; do not grant blanket skip-all-questions authority. Verify final answers reached the intended behavior, not an unrelated early stop.
5. Capture the complete exposed tool-call/result and message stream, plus stderr. A missing/incomplete trace blocks confidentiality/no-access claims. Never print trace bodies or canaries into the main conversation. Offline scanner fixtures must reject leaks in tool results, stderr and messages, while allowing safe key/path output; a synthetic live positive control must demonstrate capture before claiming a no-leak model result.
6. For P10, generate the canary inside fixture tooling, never in the model request. Check raw and agreed encoded forms in outputs/new artifacts and retain exact original input bytes and Git state. Pre-existing canary inputs are expected; newly exported values are not. Scan coverage is explicitly bounded, not proof against every encoding or malicious channel.
7. Compare results with predeclared expected bytes/refs and preserve case-level evidence. A passing run is one observation, not a universal guarantee; investigate any failure and repeat only for a stated stability question. Keep traces local with bounded retention; delete only owned disposable artifacts after inspection and retain a safe result summary. No canaries/traces in commits.

Additional expected outcomes for the high-consequence cases:

- **P11:** all affected fixture branches share the same old/new mapping; unchanged messages and author/committer metadata stay exact; merge boundaries, tags, excluded refs and remote configuration remain correct. Verify the recovery bundle in a second temporary repo without borrowing original objects. No real project history or remote publication.
- **P12:** freeze the expected remote IDs before the attempted action. Deliberate local-remote movement must block without a replacement lease. In a separate two-ref fixture, verify one success plus one injected failure, then only the missing unchanged approved action on resume; read back every ref and preserve the success. Do not simulate success using agent text alone.
- **P13:** review the actual current source-only payload/receipt contract before constructing synthetic proofs. Corrupt one binding and assert no restore/service-stop/cleanup/publication action. For a valid completed fixture, assert no replay on both relevant owning routes, preserve protected inputs and compare exact local/remote receipt evidence. There is no archive proof validator in the ledger helper to reuse.
- **P14:** require actual trace evidence for zero-state preview. For failed/deferred verification, old protections and open records survive; only actual accepted code B may be cited by later closure C, and no failed check becomes a passing closure. Existing schema validation alone is insufficient.

## Browser and host acceptance

Use a build of the inspected source and an identified browser/client. Record observed results and limitations in the owning test outcome only when actually run. Do not claim human sign-off from automation or create a default evidence/profile file.

- **P8:** both platform pages; click and ArrowLeft/ArrowRight/Home/End (including wrap); focus, selected ARIA state and visible panel agree. Directly load each panel and nested section fragment; trigger hash changes. Visit all four legacy URLs with install/update/uninstall fragments and verify final platform/method/section. Check readable content with JavaScript disabled and in print preview. The implementation uses `replaceState`; do not invent a requirement for tab-by-tab Back history.
- **P9:** test valid and invalid stored modes; System follows emulated OS changes while explicit Light/Dark stays fixed. Block storage and verify switching still works. In two same-origin tabs, change/remove/clear the saved setting and verify selector/theme agreement. If the browser cannot exercise a condition safely, report it untested rather than change OS/client settings globally.
- **P18:** use a table of concrete changes with expected proposals: a mislabeled API break still needs the applicable breaking bump; an evidenced public deprecation follows the documented normal-contract policy; prerelease comparison uses the intended normal baseline; build metadata has equal precedence but does not make distinct tag identities interchangeable; major/minor bumps reset lower components; an incomplete candidate resumes only when its identity matches. Keep 0.x project policy distinct from stable-contract guarantees.
- **P19:** Single chooses one; Multi preserves independent selections/exclusions; Input retains supplied text; Review binds approval to exact scope. Include more options than the native picker supports and verify paging/chat fallback retains all choices. Test an unsupported native element and render failure against the shared fallback order. Leave a question unanswered and verify no write/default/timeout consent, duplicate prompt or invented response. Record host-specific unavailable elements honestly.
- **P20:** verify diagrams on ship and test render into SVG with readable text, no parse-error replacement and accessible surrounding instructions. A CDN failure is a failed/unavailable rendering check, not proof the diagram source is invalid. The existing loader's major-version CDN URL is outside this test-only change; do not silently alter its versioning policy.
