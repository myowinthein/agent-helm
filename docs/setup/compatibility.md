# Compatibility and project instructions

Refactor and test prefer the same [read-only Python ledger helpers](python-helpers.html) on both hosts. The bundled implementation needs Python 3.11+ for complete structural validation and digest-bound retrieval. When Python/execution is unavailable at an eligible normal owning-state step, offer/reuse Set up Python / Continue without Python / Stop once per run. Approved available equivalent tools may satisfy the same complete validation, safe-path, resource, retrieval and preservation checks; without that evidence, dependent work remains pending. Invalid data and package defects cannot be bypassed. Refactor's source-only preview and its report-only exit and unrelated commands load no ledgers/helpers and ask no runtime-setup question. Current refactor schema 2 and test schema 3 remain unchanged; writes, source/semantic checks and approvals stay caller-owned. Copied rules need no Python runtime. See the helper guide for complete-package updates, bounded responses and fallback.

Helm has one workflow body per operation in `workflows/`. Both hosts use portable entries in `skills/` to load the shared runtime and that workflow. The manifest exposes only skills and disables automatic command-directory discovery, preventing duplicate entries while preserving `/helm:<name>` in Claude. Claude's existing invocation policy is retained; Codex's skill entries disable implicit invocation.

## Current installation

Use the current setup guides for `myowinthein/agent-helm` and `helm@agent-helm` on both clients. The repository/marketplace is agent-helm; the plugin name remains helm. Native rule storage and client instruction formats remain independent of project state. Current workflows do not convert old installations or records. See [breaking changes and one-time upgrade](upgrading.html) before using them in an older project.

## Shared scan-depth selection

Log, manifest, test and refactor use `prompts/shared/scan-scope.md` only at their existing Full scan / Gap scan depth choice. It standardizes Full scan / Gap scan recommendations using facts the caller already permits, without adding state discovery, runtime autoloading, configuration, schemas or approval stages. Repair, backlog and focused settings paths retain their own prerequisites; read-only modes gain no access or effects.

| Existing facts | Selection |
|---|---|
| Explicit supported depth/scope | Honor it under the caller's prerequisites; explicit Full scan remains Full scan without a source gap. |
| Unusable review anchor in otherwise valid inputs | Recommend Full scan of the relevant scope, retaining independently eligible repair/backlog/report-only/Skip alternatives. Gap scan cannot invent history. |
| Valid baseline and bounded evidenced impact | Recommend Gap scan with the caller's full affected-surface coverage. |
| Credible broad impact or insufficiently bounded coverage | Recommend Full scan with the observed reason; this is not approval or a silent scope upgrade. |
| Supported evidence of no source gap | Return to the caller's pending-work and no-op checks; do not declare completion from the diff alone. |

Anchor validation is local: a literal hexadecimal commit identity must resolve unambiguously to an available commit object and be an ancestor of the inspected source. Missing objects, failed comparisons and incomplete evidence stay unknown. No guessed anchors, fetches, resets or branch switches follow from this helper. Malformed/unsupported state and conflicting histories or instruction ownership remain blockers to dependent work, distinct from an unusable anchor inside valid inputs.

Age, commit/file counts and numbers of incremental runs are context, never triggers by themselves. Unknown Full-scan history does not mean no Full scan occurred. Test retains its separate prior-Full-scan coverage fact; refactor v2 retains assessed/full-scan anchors without active date/mode/count fields; Current native source anchors do not claim prior coverage. Missing headings/adapters can need narrow repairs. A valid explicitly requested Gap scan can cover broad impact completely; incomplete review follows the caller's existing checkpoint rules. Explicit requests, pending findings, lessons, settings and external freshness can justify work without source changes.

| Command | Review/selection remains command-specific |
|---|---|
| log | Full scan/Gap scan: shared project knowledge, complete per-commit lessons and the owner's accepted review marker. |
| manifest | Full scan/Gap scan: target README and affected reader workflows, with its accepted review marker. |
| test | Full scan / Gap scan: schema-3 source assessment and per-gap cases; recording findings does not certify tests passed. |
| refactor | Full scan/Gap scan: affected code and scan/backlog history; Fix Backlog remains an independent work choice. |
| env | Current value-free audit of loader, template and ignore evidence, without a scan-history baseline. |
| legal | Per-document source freshness plus independent business/provider/legal freshness. |
| normalize | Commit-message policy coverage and the affected rewrite graph. |
| adopt | Installed rule body/version/layout and instruction connection evidence. |
| ship | Publication/release ranges and provider/integration evidence. |
| archive | Fresh assessment or proven resume/completion of its fixed archive bundle. |

Only the first four consume the helper; the other six retain their specialized procedures. Log/manifest keep acceptance-before-marker rules, test keeps an authorized assessment checkpoint before implementation and separate supported closures afterward, and refactor keeps its schema-2 evidence/history and recovery-first conversion rules. No ledgers or review markers are rewritten by the selector. See each command's detail page for coverage and completion requirements.

Review markers are preserved during moves; ambiguous merged review histories are disclosed rather than stamped as freshly reviewed.

## Release planning and publication
