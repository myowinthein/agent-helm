# Design

Help agents make coherent design decisions for websites and web interfaces, including documentation sites. Select Design explicitly during [adopt](../commands/adopt.html); it is available but unselected by default, independently of Writing, Git and Safety.

## What it asks the agent to do

- Build layouts from real content, audience needs and the current task.
- Choose a visual direction when none exists, making important assumptions visible without a routine questionnaire.
- Use deliberate typography, spacing, alignment and emphasis, with components suited to the information.
- Consider interaction states, accessibility, responsive behavior and the cost of assets and effects.
- Present evidence and choices honestly, including charts, sample data and product status.

Cards, gradients, badges and animation can all be useful. The rule asks agents to reconsider automatic choices and use them where they serve the content or intended experience. It sets no visual style, novelty requirement or authorship test.

## Adapt to the surface

| Surface | Emphasis |
|---|---|
| Landing page | Relevance, credible evidence and a useful next step. |
| Product interface | Recurring tasks, comparison, feedback and recovery. |
| Documentation | Finding, reading and using information. |
| Personal site | Identity, work and expression. |

Keep project branding, tokens, component choices and known user needs in local guidance or the existing design system. Separate local guidance makes reviewed Helm updates easier than customizing the adopted copy. [Writing](writing.html) governs prose; Design governs presentation and interaction. Neither rule requires the other.

## Scope and review

Design applies to requested planning, creation, editing and critique of web surfaces. It preserves the surrounding style during targeted edits and starts no unsolicited redesign, scan, tool installation or approval process.

[WCAG 2.2 Level AA](https://www.w3.org/TR/WCAG22/) is its default accessibility reference; applicable project requirements and stronger obligations remain in force. Reviews distinguish standards, contextual usability concerns and preferences. Screenshots and automated checks alone do not establish accessibility or task success.

Checks scale to the change and available tools, while required project checks remain required. Agents report material verification limits and do not claim unperformed checks passed.
