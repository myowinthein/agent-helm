# Shared runtime

Apply this runtime before the selected Helm workflow in Claude Code, Cowork, or Codex. Run only that workflow; reading another command or a repository document does not invoke it.

## Package and workspace

The package root is the directory containing this runtime, `rules/`, `skills/`, `workflows/`, and `.claude-plugin/plugin.json`. Resolve bundled links from the actual file being read. On Claude, `${CLAUDE_PLUGIN_ROOT}` identifies the loaded package; elsewhere derive the root from the selected SKILL.md's location. Never guess a cache version or substitute another installation when a required resource is missing.

The consumer workspace is the user's selected project and working tree. Keep it as the working directory for Git, builds, tests, and generated output. Read workflow and archive-step instructions from the package; read and write project files, `.claude/rules/`, `.helm/`, `.archive/`, and recovery files in the consumer workspace. A consumer's similarly named `prompts/` or `rules/` directory is not a substitute for packaged workflow resources.

Exclude `.helm/` (including `.helm/archive/`), protected historical `.archive/`, `.claude/helm/`, and the known unsupported old state paths (`.claude/refactor-log.json`, `.claude/test-log.json`, `.claude/normalize-log.json`, `.claude/legal-manifest.json`) from source-code discovery and history/diff content rendering. Read history messages/metadata and changed names/status first; render supporting patches only for allowed source paths, excluding these current and historical state paths before their bodies enter tool output. Only the invoked owning workflow, or ship under the selected archive publication continuation below, may load or update its operational state; preserving a project in an archive does not authorize migration of that state.

Before Git operations, establish that the host's shell is operating on the selected working tree. Folder access in Cowork or a remote sandbox does not establish access to the user's local Git checkout, credentials, Docker daemon, or installed tools. If a required capability is unavailable, report it and stop the affected step without claiming completion or advancing state.

When directed, use the [local-edit Git procedure](content-sync.md) for log/manifest/env/legal/test setup and completion. Log/manifest/legal require base; env/test additionally permit established current feature branches and confirmed environment branches, and test permits maintenance branches. Refactor records/applies on base, established current feature or existing refactor/* branches, while confirmed non-base environments remain source-inspection/report only even with that prefix. Establish non-base roles from project/deployment evidence or developer classification, never names alone; eligibility does not establish safe runtime targets. All editing workflows remain local: respect current-branch eligibility and stronger project policy, block ineligible writes with a reason, and never automatically branch/switch, push/PR, integrate/promote or clean up to finish. Normalize coordinates approved existing local refs and commits its record locally; archive confirms its actual source branch/HEAD and exclusions before normal pending phases and prepares its payload locally. Ship publishes reviewed work and optional same-source targets, then offers a separately approved release on ready integrated main/master. A rerun assesses unpublished work, target handoffs and incomplete releases before declaring a no-op. Ship uses [CI gates](ci.md) and provider procedures for each route; history replacement retains its dedicated evidence/lease procedure before release eligibility; a selected private archive backup remains terminal.

**Narrow publication-state exception:** ship may probe no-follow metadata for the exact canonical/unsupported archive roots and relevant Git-native rewrite metadata, and use a normalization handoff from trusted conversation or a developer-identified private path. Those hints authorize no state contents, private-directory search, force update or backup. Before opening an archive bundle obtain its explicit inspection selection, then use only the packaged canonical root/schema/seal procedure and update only that selected bundle's publication journal/receipt. A normalization continuation reads only the identified private recovery/graph/map evidence and relevant committed bookkeeping delta as opaque provenance; never its live ledger. Conflicting candidates require scope reconciliation, not silent precedence/fallthrough. Other ledgers remain opaque. Missing procedures/evidence block dependent work. Source maintenance and agent switching still grant no operational-state access.

## Project instructions and configuration

Read the consumer's active project instructions and the bundled [Git rules](../../rules/git.md), [safety rules](../../rules/safety.md) and [writing rules](../../rules/writing.md). Respect project-specific instructions and adopted rules; loading a workflow does not install, overwrite, or weaken them. This does not install project-wide writing instructions or make writing a dependency of an existing copied Git/safety pair. Use the Git rules' **Project memory and configuration** procedure to resolve `{memory_file}`, the single owner of Helm configuration and project knowledge. Do this before dependent writes; ordinary editing workflows do not create or switch branches. `{instruction_file}` is the current host's active root entry: `CLAUDE.md` in Claude; in Codex, root `AGENTS.override.md` when present, otherwise `AGENTS.md`.

The workflow's `{memory_file}` references mean the resolved owner, including when reached through an instruction bridge. A wrapper is an entry point, not an empty or broken memory schema. Preserve wrappers and configuration ownership except for `log`'s explicitly approved shared-layout migration. `log` may compare unresolved independent/partially connected root entries or a readable root two-file cycle, following its layout procedure and asking for a resolution before Git changes; it must not silently pick conflicting settings. Other cycles/missing chains still stop. Do not change global client settings or create a second configuration owner. `log` and `adopt` describe the only layout/entry writes; other workflows must preserve the owner when saving a configuration choice.

For a fresh project with neither file, the proposed shared owner is root `AGENTS.md` on either host. Resolving that path is read-only; create it only when the selected workflow calls for it. `log` establishes AGENTS.md plus a real CLAUDE.md importing `@AGENTS.md`, using its packaged layout procedure; `adopt` has its own limited bootstrap/entry handling. Neither workflow may claim both hosts are connected while an active override shadows the shared entry. External Helm rule references are unsupported and need explicit maintenance outside adopt; log layout changes preserve unrelated instruction meaning and do not convert rule installations. A plugin package's own contributor AGENTS.md/CLAUDE.md is never consumer memory.

Adopt uses one project-local copy per selected rule and no external-reference conversion. Unsupported external pointers stop with upgrade guidance. Only log performs reviewed first-time owner reconciliation; preserve current entry/override behavior and unknown imports. New setups propose Git, safety and writing; existing setups add writing only through its separately accepted file/pointer proposal.

## Questions and authorization

`AskUserQuestion` blocks in shared workflows describe the question, choices, and whether multiple selections are allowed. In Claude, use AskUserQuestion when available. In Codex or another host, use an available question interface only if it can represent the question faithfully; otherwise show the choices in ordinary conversation and wait for the user's reply. Do not assume a plan-only input tool exists in other modes.

Preserve free-text answers, including the Claude Other response, and an explicit `none` for an empty multi-selection. A missing answer, timeout, default selection, unavailable tool, or ambiguous reply is not consent. Clarify ambiguous selections before dependent work. Do not choose all options to approximate an unsupported multi-select. Retain the workflows' existing option limits and grouping on Claude; plain chat can present those same choices.

Keep every workflow confirmation, cancellation, no-op, and cleanup path. Reuse authorization already given for the same described action; do not add another approval on top of a workflow's own confirmation. Host sandbox/tool approvals are separate technical permissions and do not answer a workflow question. Conversely, a workflow confirmation cannot bypass host restrictions. Do not pre-approve shell, push, history rewrite, publication, or deployment tools through skill metadata.

`Write` and `Edit` refer to full replacement and a targeted patch respectively; use the host's equivalent file tools while preserving those semantics and the workflow's read-back verification.

## Delegation and checkpoints

Workflows that explicitly name delegation, or a user's explicit delegation request within the caller's existing scope, may use the host's available read-only workers when invocation and active instructions permit. Substantial refactor/test Full scans and large log investigations benefit from bounded assignments; other named independent investigations may delegate proportionally. Small/ordered work, especially ship and adopt, defaults to the parent; this is not a blanket ban on permitted unusually large independent read-only work. Queue within actual available slots and any caller ceiling, never using concurrency as a total coverage cap. Without delegation cover the same scope sequentially or report incomplete. Pass actual package/consumer paths, source identity, exact scope/depth, applicable instructions/overrides, policy context and safety restrictions explicitly; workers may not inherit them. Follow the investigation contract only when the caller loads it, not as runtime autoloading or a no-scan prerequisite. Fresh context is not a filesystem sandbox.

On Codex, the parent owns code edits, Git mutations, provider operations, ledgers, and state writes. Permitted read-only local Git object/metadata inspection is investigation, not mutation; caller/tool restrictions still apply. Workers return findings plus inspected identities/depth, unresolved edges and unread remainder, not a finding count as proof of coverage. They do not execute project code, perform Git mutations or provider operations, read operational state, start another workflow/worker, answer user questions or update aggregate state. Parent reconciliation uses exact identities and permitted own history; available read evidence cannot prove semantic understanding. Process editing clusters and waves sequentially. Keep Claude's existing wave behavior, but never promise a fresh-session mechanism the host cannot provide; continue from the recorded checkpoint in the current session or report the precise resume point.

Refactor/test's normal owning-state steps lazily load `prompts/shared/ledger-helper.md` for the parent's preferred packaged read-only Python 3.11+ ledger validation/retrieval. Resolve `helpers/` from this same loaded package. Missing Python/execution uses that reference's once-per-run Set up Python / Continue without Python / Stop choice; available equivalent tools must satisfy the same complete validation, bounded retrieval and preservation checks. Without them only dependent work stays pending. Do not load/invoke helpers or offer runtime setup during shared-runtime setup, refactor's source-only preview and its report-only exit, source investigations or unrelated commands. They add no writer, migration, permission grants or rule dependency; invalid data and package defects retain their blockers.

Use canonical `.helm/` project state on both hosts. Refactor/test/normalize/legal load the [project-state procedure](project-state.md) only at their eligible owning-state entry, validate only the current schema and stop on unsupported leftovers without conversion. Archive and ship's selected archive backup procedure alone use the [canonical bundle procedure](../../workflows/archive.md#resolve-one-archive-root) at `.helm/archive/`. Old archive evidence remains protected and stops that route with upgrade guidance; no relocation, old-state reader or replay occurs. All other state stays opaque. Checkpoints require their owning source evidence, verified outputs and approvals. Update both complete client packages and start fresh sessions; concurrent writers are unsupported. Never write consumer results into the installed plugin.
