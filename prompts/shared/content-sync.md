# Shared local-edit Git procedure

For log, manifest, env, legal and test. Apply only when the invoking workflow selects a write. This helper never loads another command's state and never publishes. Adopt and refactor use the same local-only boundary through their own preparation; normalize owns its coordinated existing-ref rewrite.

## Prepare the current branch

Resolve the effective instruction/configuration owner and applicable local commit policy (`git-auto-commit`, default false). Record current/original branch and starting HEAD. Resolve the actual main/master `{base_branch}` from instructions/default branch/refs. Log, manifest and legal require that current base. Env and test also allow an established existing current feature branch or a confirmed current environment branch; test additionally allows an established existing current maintenance branch. These are caller-specific eligibility rules, not new configuration settings. Otherwise report why writes are blocked and offer only the caller's read-only path. Do not fetch, pull, update, create, select or switch branches. A missing/ambiguous base or detached/no-HEAD checkout blocks writes, except log's explicit non-Git bootstrap, which skips Git rather than initializing it.

For env/test on a non-base branch, establish its eligible feature/maintenance/environment role through actual project instructions, deployment configuration or explicit developer classification. A branch-name prefix alone proves neither role, ownership nor safety. Reuse known evidence; ask only when classification remains unresolved, before dependent write approval. Stronger project restrictions still apply. Eligible roles permit the same approved workflow actions; recommendations do not split fixes or modes by branch. Recommend feature/main for shared fixes, targeted tests or intentional configuration work on an environment branch, and base for project-wide hygiene/assessments. The actual base retains its base role even if deployed to production. Branch eligibility does not establish isolation or authorize live-service actions: inspect actual script/hook/runtime targets and retain existing effect approvals. Environment-branch shared fixes may need deliberate upstream application and can be overwritten by later integration; preserve intentional differences and never synchronize branches or ignored worktree-local env inputs automatically.

Require the caller's clean index/worktree and no in-progress operation. Never stash, reset, absorb or commit unrelated work to proceed. Only an explicitly selected current canonical input owned by this invocation may receive the caller's documented treatment; other owners' state, pending tracked work, conflicting drafts and unsupported old paths remain blockers. This helper never interprets or migrates state.

For log reuse the frozen `{run_auto_commit}` and approved absent-key overlay only while raw owner/declarations/overrides still match `{run_config_baseline}`; pending settings are not persisted policy. Other commands preserve current configuration. Re-read effective instructions/source before writes, and stop unexpected input/policy drift. Record `{branch}` as the actual current branch, not a planned workflow branch. Existing active copied rules may require older branching behavior: reconcile/update them explicitly rather than bypassing them or creating a branch to bypass them.

## Finish verified local work

The caller verifies its own outputs/state, stages literal exact approved paths and obtains commit approval under `git-auto-commit` and stronger task-specific requirements. Legal documents always retain explicit content/commit approval. Do not recommit earlier units, create empty/cosmetic cleanup commits, or advance a checkpoint without its source evidence. Env's approved local-only edits remain on disk and are never staged as secrets.

A failed/declined write, check or commit preserves actual files/index/refs, prior successful work and preserved inputs; report partial/draft/pending status. A genuine no-op writes/commits nothing. Do not require a remote, published source SHA or provider access merely to finish local work. Local source checkpoints may refer to verified local commits under the owning workflow's contract; they certify only their inspected snapshot/scope, not another branch, publication or passing tests. After integration or history changes, the owning workflow revalidates ancestry/context and reassesses invalid anchors rather than substituting a merge tip or merging state automatically.

Finish on the same branch. Never offer push/PR, integrate, promote, create/switch/delete a branch or perform automatic cleanup/return checkout. Report inspected snapshot, verified local outputs/commits, drafts/checkpoints and unperformed checks; state publication was not performed and the developer may invoke ship later. This is a completed local workflow, not a suspended PR/finalization phase. A later ordinary invocation reassesses normally; an explicitly identified partial local run resumes only missing verified eligible work.
