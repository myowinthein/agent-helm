# Recover a rewritten review anchor

For log and manifest only, at their existing read-only marker validation. Load lazily when one unambiguous literal hexadecimal marker is missing its commit or is no longer an ancestor of the pinned local review tip. A missing, malformed or multiple marker supplies no recovery identity. Valid anchors use the normal route. Explicit Full scan and layout/repair/style-only work need no recovery prerequisite when they do not depend on the old baseline. This restores an earlier review's identity, never new coverage or permission to write.

## Ordered local evidence

Try these sources in order, stopping at a uniquely verified correspondence unless other known evidence conflicts. Expand abbreviated IDs only to a unique original commit identity. Use available safe tools; unavailable execution needs no installation/setup question. Bound local processing and model output to the marker, candidate objects and relevant mapping chain; inability to complete required verification leaves recovery unsuccessful.

1. **Preserved normalize maps.** Use only the location, safe discovery and bounded I/O rules in [local handoff](normalize-handoff.md), via its read-only `discover` helper or safe equivalent. From identified entrypoints, read only relevant repository/object identities, named current-run maps and verification inputs. A locator or recorded success flag is not proof. Verify relevant original/new objects and source-preserving correspondence; follow repeated rewrites only through independently verified links, not adjacent tip equality or folder dates. Do not load ship's publication procedure or require publication proof.
2. **Native backend map.** Resolve the working tree's actual Git directory and shared common directory; check only their `filter-repo/commit-map` files, deduplicating equal locations, with safe no-follow regular-file reads. Retrieve the old ID's mapping and necessary links locally, not a prompt dump. This map may be overwritten or composed across runs; verify its result against actual objects rather than assuming it describes the last invocation. A zero/deleted target, cycle, conflicting row or unavailable intermediate is not a usable baseline. See the [backend documentation](https://github.com/newren/git-filter-repo/blob/main/Documentation/git-filter-repo.txt).
3. **Existing local objects.** If the old commit remains available, index the pinned tip's ancestry by tree/metadata to find candidates, then verify source-preserving equivalence. Reflogs and retained refs/tags may locate relevant old tips or objects when direct evidence is insufficient; they are discovery hints, not old-to-new proof. Reuse verification instead of repeatedly walking history. Do not scan all objects, create `lost-found`, fetch, restore a bundle or import objects.

These are read-only exceptions for this procedure, not access to normalize's live ledger, archive bundles, unrelated recovery payloads, private configuration or credentials. Reuse the handoff's ownership/path/permission checks for identified private inputs; parse only necessary identity/map fields locally and keep sensitive unrelated fields out of output. No personal-folder, other-clone or private-transcript search, network lookup, saved-script execution, ref/replacement creation, locator registration, repair or cleanup. An explicitly supplied evidence path can be used under the same checks but is never a new required path question. Source maintenance still accesses no real operational evidence.

## Verification and result

Read actual commit objects with replacement interpretation and lazy fetching disabled; existing graft/replacement ambiguity prevents recovery. Require a unique new commit reachable from the pinned review tip, the exact same complete source tree as the old reviewed snapshot, and consistent preserved metadata and ordered parent correspondence across the relevant rewrite graph/boundaries. Message/signature differences need verified rewrite evidence explaining them; otherwise the object-matching fallback requires exact raw commit contents except mapped parent IDs. Identical trees alone, titles, dates, patch IDs, reflog labels or a claimed mapping cannot prove correspondence. A rebase, cherry-pick, squash or file-changing filter is not automatically a source-preserving normalization. Missing old objects require equivalent original object/graph proof in the identified evidence; a bare map row is insufficient.

Resolve only the one marker; conflicting viable matches, incomplete proof, unsafe/unavailable inputs or resource limits never justify a guess. Continue independent permitted methods when one source is unusable, but do not discard a known conflict to accept a convenient match. On failure, briefly report the limit and use the caller's existing Full scan / Skip alternatives; manifest retains its independently eligible repair/style-only routes. No recovery picker, mandatory manual lookup or new approval gate follows.

On success, retain transient `{original_anchor}`, `{recovered_anchor}` and verification evidence. Report one short note, then use the recovered ID for the normal impact index, Gap scan / Full scan / Skip choice and applicable no-op rules. Recovery does not itself establish that every intervening change was reviewed or permit Gap scan with incomplete history. Revalidate the marker, objects, source tip and relevant proof before dependent work; changed inputs invalidate their dependents.

## File writes remain caller-owned

Do not edit a marker during discovery. Include any proposed old-to-new marker repair in the caller's existing output review and reuse sufficient approval; no separate recovery confirmation or commit is added. A repair retains the earlier assessment and may accompany approved partial work without claiming a new completed review. Only a separately complete, eligible assessment advances to `{review_head}` under the caller's normal rules. Skip, Cancel, explicit read-only and genuine no-op exits write nothing; a valid in-memory recovery need not create a bookkeeping-only commit. Apply normal branch, clean-state, local-commit and readback rules, preserving all other bytes and showing actual stored versus recovered provenance in the result.
