# Step 5 — Prepare the local archive payload

Finish the frozen project locally and commit the explicitly reviewed payload, then stop. Never ask to push, select/validate a required private destination, create a PR, change remote refs, clean up branches/remotes or create the remotely sealed completion receipt here. The developer later invokes `ship archive` to publish and verify the backup. Follow the orchestrator's validated `{archive_root}`, inventory and resume proof, only at canonical `.helm/archive/`; no relocation or new state schema.

## Preserve source and local work

Use the recorded source branch/commit and current verified checkpoints; never switch/create a branch. Preserve local names, tags, source remotes, protected instructions/rules/imports, opaque other-owner state and unrelated edits. Inventory additional branches/tags/submodules/LFS/hosted artifacts as captured or excluded; a source payload does not automatically preserve every ref or external object. Never merge unmerged work or clean up to finish. Local source/configuration and explicit project policies remain binding. A private destination and published source SHA are not prerequisites for local preparation.

Load only archive's own validated bundle and four prior reports. Review exact files and required local actions before approval; auto-commit/tool permissions never replace archive's explicit payload content/commit approval. Failed/declined work preserves drafts and prior results. Verification deferral remains in effect; no unrun checks become passes.

## Task 3 — Recovery storage and LFS

Before the local payload commit, revisit Step 2's rough storage plan using actual unique artifacts, sizes/checksums and free space. Assign each artifact to regular Git, supported LFS with actual local objects, or an explicitly accepted separate/local-only exclusion; Cancel preserves existing work. Use known provider evidence when available and ask a provider preference only if it changes this material storage decision. Unknown destination support does not make arbitrary large blobs safe for regular Git: record compatibility limits or accepted incomplete preservation. No recovery artifacts means not applicable.

Keep exact private destination/account/plan/quota/retrieval verification with ship archive; unavailable remote access does not block local preparation. Record unknown provider-specific requirements as pending rather than imposing GitHub's regular-file limit on every host. Local storage verification is not remote backup verification.

For LFS, verify local tools/object availability and any already evidenced storage requirements without installing tools or configuring global settings. Review repository-local hook/config/attribute effects before setup, preserving existing custom hooks unless their specific change is approved. Track exact approved paths/patterns and verify their pointers and actual local objects. Adding `.gitattributes` does not retroactively convert historical regular blobs; a history/limit problem needs separate resolution, not an implicit rewrite. Provider support or a Git pointer alone is not proof the actual recovery bytes are retrievable.

For local-only/separate storage, show exact exclusions and any approved ignore rule. Already-tracked artifacts require separately reviewed index removal, preserving files locally; ignoring them alone does not untrack history. Verify any supplied separate copy/receipt by expected identity/checksum where possible. Otherwise report **prepared locally; recovery kit incomplete/local only**, never a complete backup/offline-recovery claim. The separately approved portable-copy action may later supply copy evidence, but do not preclaim it in the seal.

Record meaningful changes/exclusions in the existing inventory. No directory-wide staging, global LFS changes or automatic cloud upload. Cancel preserves actual prior restoration work and journal; this command never publishes.

Preserve native originals. Retain existing portable views or propose useful conversions only with available approved tools, including licensed tools within their authorization; no installation, activation, payment or unapproved upload merely to convert. External material requires developer-supplied exact local paths, not a personal-drive crawl or authenticated remote fetch. Show exact old/new paths, value/reason, fingerprints and every necessary reference edit; wait for the missing approval before mutation. Do not assume a directory/filename is unreferenced or needlessly shuffle all media. Unknown external consumers favor retaining the current path.

After an approved move, update current setup/index/metadata/configuration and inventory/checkpoint paths; verify recovery dependency and navigation closure. Keep earlier approved reports verbatim and record legitimate supersession. A changed recovery configuration requires affected reassessment and any missing verification; deferred checks stay unverified and block only claims/actions that require them. No completed local preparation with known broken reference wiring.

Compare `{archive_root}/files.json`, expected source/checkpoints and actual index/worktree. Show exact created/modified/deleted files, approved unchanged/untracked preservation inputs and exclusions. Include approved restoration/configuration outputs outside docs/recovery. Recheck current containment/protected paths and latest legitimate fingerprints. Exclude real credentials, private client settings/records and secret-bearing reports/data/images/artifacts. Inspect actual selected recovery bytes, not just LFS pointer diffs. Missing material safety evidence blocks inclusion/commit. Known selected-history secrets block later backup publication; do not rewrite history/tags or protected originals to fix that. Show findings without values and leave separate reviewed resolution.

Prepare the factual fifth report with files, source scope, retained refs/remotes, per-artifact storage choices/local LFS identity, retained/consolidated supplementary materials, actual service-stop/move results, performed/deferred checks, exclusions and recovery instructions. It must say **prepared locally; remote backup not published/verified**. Do not invent a payload SHA before committing, remote destination, receipt or shutdown/recovery success. Present the report and exact payload diff with **Commit reviewed local archive** / **Leave uncommitted**. The approval is local only. Reuse valid same-action content approval; new material inputs require renewed review.

On approval, keep cursor 4 and phase `prepared`; a remote may remain null for local preparation. Persist/read back the approved fifth report, its checkpoint digest/outputs and meaningful inventory/source metadata before staging. Stage literal exact approved paths and tracked deletions only, never directories, `git add -A`, bare `add -u` or opaque state. Inspect the complete index, local LFS objects/pointers and all metadata. Commit `chore(archive): seal project archive` (or compliant equivalent) and verify the actual payload parent/tree, archive ID, report and manifest.

Record the verified payload SHA in conversation/existing private handoff evidence, without a cosmetic follow-up tracked write/commit. The committed journal intentionally remains cursor 4/phase `prepared` with a null payload ID for fresh local preparations, avoiding self-reference and keeping a clean local result. A later invocation may recover that exact payload only from archive ID, expected parent/source, committed prepared journal, complete reviewed report/inventory/output fingerprints and local Git proof, never its subject alone. If extra unrelated commits/content intervene, reconcile rather than silently including them.

Finish on the same branch with **ARCHIVE PREPARED LOCALLY**, actual payload SHA or uncommitted status, validated root, evidence/limits and `ship archive` as the optional next action. No push/PR prompt, new branch, return checkout, remote cleanup, receipt-prepared cursor 5 or claim of a sealed backup. A failed/declined commit retains actual drafts/cursor and cannot certify local preparation.
