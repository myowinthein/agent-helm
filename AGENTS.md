# agent-helm

## Project Identity

**Name:** agent-helm (plugin name: `helm`)
**Stack:** Markdown workflows with preferred standard-library Python 3.11+ read-only ledger helpers for normal refactor/test state paths and an approved equivalent-tool fallback when Python/execution is unavailable; a Jekyll + just-the-docs GitHub Pages site lives alongside them in the same repo. Copied rules and refactor's source-only preview need no Python.
**Purpose:** A workflow plugin for developers using Claude and Codex. Agent Helm provides ten shared workflows for recurring development tasks and three rule files covering Git work, operational safety and clear writing.
**Blast radius:** Changes to `workflows/*.md` affect every user who has the plugin installed. Changes to `rules/` affect every project that adopted them via `/helm:adopt`.

ship-method: direct
git-auto-commit: true
readme-style: custom

## Dev Commands

No install/build step for the plugin itself: its skills and workflows are Markdown files, with packaged standard-library Python helpers loaded only at eligible normal refactor/test state steps. Run `ruby scripts/test_plugin.rb` for offline package checks and `ruby scripts/check_clients.rb` for native CLI discovery. For the Jekyll docs site, use `bundle install`, then `bundle exec jekyll serve` to preview or `bundle exec rake test` to check packaging, links, images and HTML. The docs Actions workflow builds the site only; it does not run the deferred tests or native client checks.

Publication: invoke `/helm:ship` in Claude or select ship in Codex. One workflow assesses current source/PRs, optional independent same-source targets, verified normalization handoffs, selected prepared archive backups and release candidates. Ship-method direct/pr governs source/target publication independently of branch topology/team size; existing features remain their source and main/env share one proven helper across their requests. Source publication and pending reviews are distinct. After successful selected work, ready integrated main/master offers an approved version/tag/optional hosted release, including no-push reruns; reuse an incomplete version before another bump. First releases use complete scoped history and normalization-only IDs are excluded through verified release correspondence. Targets may remain behind when current source is published. History replacement keeps private proof/fixed leases, then can return to release assessment; selected archive backup keeps payload/receipt gates and finishes without release. Discovery grants no live-ledger access: use identified private evidence and metadata-only archive detection followed by explicit bundle inspection. No shipping ledger or new state schema; execution/provider validation remains deferred.

## Architecture Pointers

- `skills/*/SKILL.md`: the only ten portable entry points, loaded by Claude and Codex. Keep the manifest's `commands: []` safeguard and do not reintroduce legacy command adapters or Codex's generated `source-command-*` entries.
- `workflows/*.md`: canonical workflow bodies; `prompts/shared/runtime.md` resolves package/workspace paths and host capabilities. `prompts/shared/content-sync.md` defines local editing phases; ci.md gates ship integration/promotion. The packaged history-publication.md and archive-publication.md helpers are explicit ship-only protocols, not discoverable skills.
- `prompts/shared/scan-scope.md`: depth recommendations only for log/manifest/test/refactor at an existing Full scan / Gap scan choice, never runtime-autoloaded and granting no additional state access.
- `prompts/shared/investigation-evidence.md`: lazy investigation-only contract for transient exact inventories, purpose-specific depth, evidence-based exclusions and worker/parent coverage. No runtime autoloading, new state or no-scan prerequisite.
- `prompts/refactor-ledger.md`: authoritative native schema-2 refactor model and bounded working views, loaded only at the owning-state entry. No older-format reader or automatic conversion.
- `helpers/helm.py`, `helpers/helm_lib/`, `helpers/ledger-contract.json`: preferred shared read-only `ledger-check` / digest-bound `ledger-view` for current refactor/test records. `prompts/shared/ledger-helper.md` owns runtime/interface instructions and the once-per-run Set up Python / Continue without Python / Stop choice for unavailable execution. Available equivalent tools must meet the same complete validation, safe-path, resource, retrieval and preservation checks; otherwise dependent work stays pending. Invalid data and package defects remain blockers. The JSON contract owns structural shapes/enums/limits and workflow prose owns semantics. No helper writer, Git/network/project-code execution, migration, new ledger schema or persistent fallback preference. Parent-only, lazy normal owning-state access; never run against live records during source work. Execution testing remains deferred.
- `AGENTS.md`: shared contributor instructions and the single owner of project knowledge and Helm configuration; `CLAUDE.md` imports it and adds Claude-specific instructions.
- `scripts/validate_plugin.rb`, `scripts/test_plugin.rb`: offline packaging checks, including rejection of reintroduced legacy command adapters; `scripts/check_clients.rb` optionally verifies native CLI discovery through Claude's plugin inventory and a temporary Codex install's actual `skills/list` catalog, not just `plugin/read`. It does not alter user installations or call models.
- `rules/git.md`, `rules/safety.md`, `rules/writing.md`: shipped rule files, installed as reviewed shared copies via `/helm:adopt`; the runtime loads bundled rules during Helm workflows
- `prompts/archive/step{1-5}-*.md`: sub-step files for `/helm:archive`; `workflows/archive.md` is the orchestrator that reads and sequences them
- `docs/commands/*.md` (+ `docs/commands/archive/`): human-readable detail pages per command, published as Jekyll site content; not command source
- `docs/rules/`: detail pages for the three rule files
- `.helm/*.json`: canonical shared records for refactor (native schema 2), test (schema 3), normalize and legal (schema 1). Only eligible owning workflows access records. The shared state helper stops unsupported old paths without reading or migrating them; feature edits leave operational data alone.
- `.helm/archive/`: the only resumable current schema-1 archive root. Known old bundles and all recovery assets remain protected; an old-bundle exists-only guard stops archive routes with upgrade guidance, without reading/moving them.
- `.claude-plugin/plugin.json`: the version file; bump this on every release
- `.claude-plugin/marketplace.json`: marketplace registration metadata; `/helm:ship` keeps its `plugins[].version` in sync with `plugin.json` automatically
- `_config.yml` + `Gemfile`: Jekyll/GitHub Pages site config; `docs/` files serve as site pages
- `.github/workflows/docs.yml`: resolves the latest stable Just the Docs release and builds on main pushes, PRs and manual dispatch; only main deploys through GitHub Pages Actions. It builds docs without running plugin/client/test workflows.
- `_includes/header_custom.html`, `assets/js/theme-switcher.js`, `_sass/custom/custom.scss`: System/Light/Dark selector with a site-specific saved preference; `_includes/head_custom.html` loads it before content renders and retains Mermaid support.
- `docs/setup/claude.md`, `docs/setup/codex.md`: platform setup pages with horizontal Desktop app / Terminal tabs. `_includes/setup/` owns the four shared instruction bodies, `_includes/setup-tabs.html` renders them and `assets/js/setup-tabs.js` supplies keyboard/fragment navigation. Existing standalone URLs reuse those bodies but stay out of navigation/search.

## Domain Rules

- `docs/commands/*.md` are detail pages, not command source: editing them never changes command behavior; the real definitions live in `workflows/*.md`.
- `prompts/archive/*.md` must remain supporting prompts, not discoverable skills: turning each step into a standalone command would break `/helm:archive`'s single-entry orchestration.
- Refactor native schema 2 and test schema 3 store stable per-finding/case identity, independent assessment/decision/closure evidence and real source anchors. Preserve unknown/untouched and useful closed records. A recorded assessment is not passing verification. Unsupported versions/variants stop without conversion/reset; missing files are created only by meaningful eligible owning assessments. Normalize and legal retain schema 1.
- Shared scan selection applies only to log/manifest/test/refactor: honor explicit scope, distinguish unusable anchors in valid inputs from malformed/conflicting state blockers, and recommend depth from bounded/broad impact rather than age/count thresholds. Focused/read-only paths retain their prerequisites; coverage and checkpoints stay caller-owned. Refactor v2 retains assessed/full-scan source anchors with no active mode/date/counter fields; The other six workflows retain specialized selection.
- Standardize depth labels to Full scan / Gap scan for log/manifest/test/refactor, using only current request labels. Investigation inventories exact paths/commits independently of old findings, applies evidence-based exclusions and reconciles required depth plus cross-unit edges. Refactor Full reads eligible first-party implementation/tests in full; test reviews component behaviors and relevant tests; log traces all packages/topics and every Gap commit; manifest verifies claims plus missing reader surfaces. Specialized commands keep their scopes. Workers return inspected identities/depth, no-finding areas and unread remainder, only under host/invocation/policy permission; parent owns all mutations/state and uses permitted history. Search hits, matching counts, time, findings or effort prove no semantic completeness. Inventories stay transient; required unread work follows caller checkpoint limits, without schema changes or retroactive checkpoint resets.
- Safety classifies actual effects as routine in-scope work, explicitly authorized consequential operations or blocked/prohibited effects. Reuse specific human requests/concrete approved plans while target/content/effects match; ask only for missing facts or authorization and keep stronger workflow/provider gates. Ordinary targeted edits may include dirty/untracked files without discarding unrelated work; no new clean-tree/backup form follows. Review material wrapper/hook/generated-operational effects, use minimal scope/access and reconcile actual results before safe unchanged retries; never blind-retry, replace a fixed lease or auto-rollback over user work. Secrets cannot be leaked as an approval shortcut. Workers carry constraints without approval authority and one parent owns consequential mutations; Markdown guidance is separate from app approvals and enforced permissions. Live state access boundaries remain unchanged.
- Docs pages (`docs/commands/`, `docs/rules/`) must stay behaviorally consistent with the command/rule files they describe, but nothing enforces this automatically; drift is caught only by manual review or a `/helm:refactor` pass.
- Test selects specialist techniques from evidenced needs, meaningful expected outcomes and concrete execution limits through its existing plan/setup approvals. Preserve reviewed visual references, replayable generated-input failures, actual workload/mutation/recovery evidence and separate human sign-off. Prior assessments do not certify newly considered techniques; reassess relevant selected context without forced rescans, new modes/settings or per-technique ledger fields. Initial source inspection stays static; case-level checkpoints retain branch/approval and local-completion rules.
- Existing tests default to Keep; scoped Improve/Consolidate/Replace/Remove actions need concrete plan approval, preserved/superseded guarantee evidence and verified replacement/remaining coverage before retirement. Deferred verification preserves old protections. Case actions and their actual closure evidence persist; detailed execution/mapping plans stay transient. Cleanup decline, Keep, nonselection or pending checks never invent human decisions or close findings. No separate maintenance mode is introduced.
- Test priorities describe residual missing protection: High for evidenced severe exposure (even rare) or meaningful impact with credible high likelihood, Medium for meaningful recoverable failures, Low for useful minor protection; unknown important impact needs clarification. Categories/layers/coverage counts never fix severity. Group proposals by module/behavior and allow exact cases, groups or tier filters; small plans use existing approval, large sets offer Recommended / All ready / Choose / None with faithful picker/chat fallback. Selection is not authorization; preserve dependencies without silent additions, real case tiers and visible unselected/blocked/cleanup/manual work. None does not authorize a ledger write.
- Test tooling discovery stays static and transient, resolving commands and dependency ownership per package/layer without a blanket evidence hierarchy or tool records in test-log/profile/config files. Distinguish declared readiness and restore/add/repair/upgrade; review compatible versions, exact paths and implicit restore/build/download/hooks in the concrete setup approval. Verify the intended runner/configuration with actual relevant evidence, not install success, version output or zero cases alone. Preserve project tooling and unrelated dependencies; unexpected changes/failures stop dependent work. Restore-only work without tracked changes needs no empty setup commit.
- Log/manifest/legal/adopt require current actual main/master for Git-backed writes, retaining explicit no-Git bootstrap exceptions. Env/test also permit established current feature branches and confirmed current environment branches, and test permits maintenance branches; confirm non-base roles from project/deployment evidence or developer classification, never names alone. Preserve runtime-target/effect gates, intentional environment differences and worktree-local ignored env inputs; no branch synchronization follows local fixes. Ineligible writes block without checkout. All finish locally on the same branch with no workflow branch, push/PR prompt, integration/promotion or cleanup; preserve inspected-snapshot checkpoints, local commit and stronger content-review requirements. Existing adopted old policies need reviewed update/reconciliation.
- AskUserQuestion caps at 4 options: preserve independent choices in dynamic lists (environment branches, refactor findings/categories, legal documents) through paging or conversational selection when needed. Never silently truncate or force unrelated choices together to fit the picker.
- `README.md` ships in three real contexts (Jekyll site homepage, GitHub.com's own renderer, the distributed plugin package via `marketplace.json`), only one of which resolves relative links to `docs/`. Its doc-page links and banner image use absolute `https://myowinthein.github.io/agent-helm/...` URLs for this reason: don't "simplify" them back to relative paths.
- Refactor records/applies locally on current main/master, an established existing current feature branch or an existing current refactor/* branch. Confirmed non-base environments remain source-inspection/report only even with that prefix; unresolved roles block writes. Recommend targeted feature cleanup without restricting modes. No branch creation/selection/switch, publication/PR/integration or cleanup follows. Preserve actual same-branch source/ledger provenance, Backlog root-anchor rules, verification and resumable coherent checkpoints.
- Refactor priority is evidenced improvement value/present burden (High substantial, Medium meaningful/localized, Low small/concrete), independent of safe/needs-review risk, effort/readiness and scan mode. Revalidate relevant stored tiers without bulk rewriting. A genuine fully assessed but unrankable finding uses priority unknown plus a clarification blocker, held outside ready/recommended work; uncertainty about value is distinct from incomplete coverage. Completed Full scan/Gap scan can record it and advance appropriate roots; actual incomplete scans still write no incomplete checkpoint. Group findings by module/behavior with exact IDs and category/priority/risk filters. Small plans reuse approval; larger sets use Recommended / All listed ready / Choose / None, preserving held work and exact exclusions. Selection never silently adds related/prerequisite findings or grants edit permission. None preserves prior authorized assessment checkpoints and authorizes no new write/skip.
- Refactor uses six defined display perspectives with stable raw values and IDs: architecture/boundaries, contracts/state consistency, clarity/maintainability, performance/resources, test maintainability and dependency/integration boundaries. Transient per-package/version/target context guides relevant official research across stacks; label requirements, constraints, optional patterns and inference without executing project code/discovery or creating profiles/config. Principles/paradigms and web architecture are contextual, never forced patterns. Test edits preserve mapped scenarios/assertions/fixtures/layers/environments/regression context and selectors/consumers; verify replacement protection before companion retirement. Missing/stronger protection and independent test strategy/layer/runner work are explicit test follow-ups, without cross-ledger access/IDs or automatic invocation. Deferred required verification keeps test retirement/substitution/weakening plan-only; approved additive guards preserve protection. Taxonomy changes never justify state migration or bulk rewrites.
- Refactor source-only preview and its report-only exit access no state. Fix Backlog preserves assessed/full-scan roots; Apply records actual code B before closure ledger C. Skip/defer/accepted-risk stays open/held. Strict complete native-format validation, bounded working views and ID-keyed updates preserve unknown history without full-ledger prompt dumps. No imported representation or conversion profile is supported.
- Archive pending phases confirm actual source branch/full HEAD and exclusions, then prepare only reviewed local work on that branch. Canonical current schema-1 payload/receipt proofs, approvals and report-only rerun safeguards remain. Only ship's archive backup procedure publishes; historical old bundles/recovery assets remain untouched and require explicit maintenance outside current resume.
- Archive discovery may hand off component setup/config/data/dependency evidence within its existing report. Step 2 restores, records evidence and offers a developer check before finalizing the approved cross-stack freeze, keeping original safe inputs unless another dataset is explicitly chosen. API materials use Retain/Repair/Create/Skip with conditional environment files. Archive owns its README information contract independently of manifest: orientation in the index, ordered procedures in setup, full artifact identities/provenance/storage/verification in human Markdown metadata. Consolidate only useful supplementary BA/design/history material; choose per-artifact Git/LFS/explicit local-only storage before the payload commit. Output/naming guidance adds no mandatory artifacts, schema, phase or migration and preserves older reports.
- Adopt is copy-only using the verified loaded package and one shared local copy per approved rule. Existing projects opt into writing separately. Preserve per-file custom/rollback decisions, exact body/marker evidence, source checks and readback before owner pointers. Only agent-helm markers are managed; external references stop with upgrade guidance. Log retains reviewed first-time shared onboarding; adopt installs no reverse bridge and converts no old references. Static connectivity is not native-loading proof.
- Generic prose policy lives in rules/writing.md and is loaded by the shared runtime. Keep commands and Git/safety rules focused on their own content, format and protection requirements rather than duplicating writing guidance.
- `/helm:legal` offers a no-drafting exit when its scoped scan finds no signals, or a source-only exit when complete source review finds no relevant changes or other known gaps in existing applicable documents. Neither writes/migrates state or certifies legal currency; explicit refreshes and material unknowns still require review. Preserve existing legal clauses through targeted edits by default, with mandatory legal content/commit approval before recording complete changed documents.
- Legal prefers existing approved text, with optional owner-supplied trusted baselines for new drafting and current applicability checks. Show important claims and their actual evidence/owner/legal basis, concrete wording issues and specific legal-review decisions before approval; a separate drafting critique is optional, never legal validation or a required second-model dependency. Templates establish no project facts or commercial choices. Keep assessment/critique details outside public legal text, state and commits; no new configuration/profile/schema is introduced.

- Normalize defaults message review to current/requested scope and rewrites all affected existing local branches together after the existing warning/confirmation. Preserve shared-ID mapping, unaudited unique messages, graph/recovery/signature/tag/worktree safeguards and schema-1 truthful local checkpoints. Commit the eligible record locally on the current permitted branch without remote dependencies or a bookkeeping branch/PR. Keep exact private old/new tips/map/bundle evidence for ship's history publication procedure; only that ship route can publish reviewed histories, with fixed leases for replacements and fresh approval for all included work. Never read live normalize state from ship or infer a rewrite from divergence.

## Behavior Rules

When consulting Claude for a review or discussion, use `claude --model claude-sonnet-5-5 --effort high`, verify the returned model metadata, and do not substitute a model or effort without the user's approval.

- Run `/helm:ship` to publish work and optionally approve its internal release stage on ready main/master
- Conventional Commits required on every commit (scope is mandatory)
- No PRs, no feature branches: commit directly to main
- `git push` always requires its own confirmation, even with `git-auto-commit: true`; the commit itself may be silent, but push is not

## Hard Safety Rules

- Do not inspect, edit, or migrate operational Helm state during feature work: `.helm/*.json`, `.claude/helm/*.json`, the known flat legacy `.claude/{refactor-log,test-log,normalize-log,legal-manifest}.json` files, and archive bundles under `.helm/archive/` or `.archive/`. These are operational records, not source. Only their explicitly invoked owning workflows may read/update them under packaged procedures. Narrow exception: ship's archive backup procedure continues its one validated bundle publication journal/receipt; ship's history publication procedure may read only identified private rewrite evidence, never its live ledger. Feature work still accesses no operational records.
- Never delete or rewrite published tags: users pin to specific versions
- Never commit secrets, credentials, or real user data (none expected in this repo)

## Known Traps

- **Refresh the whole plugin after an update.** Use the client's plugin update and start a fresh session. If a Claude cache remains stale, inspect the exact loaded path in `/plugin` and refresh the complete package from the matching marketplace checkout (`.claude-plugin/`, `assets/`, `skills/`, `workflows/`, `prompts/`, `rules/`, `helpers/`, README and LICENSE), then reload. Never copy only `skills/`: entry points require the packaged runtime, workflows and helper contract. Never select a cache version by lexicographic `tail -1` or mix versions.
- **Don't "fix" `prompts/` or `docs/commands/` by moving or redefining them.** See Domain Rules above: archive steps remaining supporting prompts, and `docs/commands/*.md` not being command source, are both easy mistakes to reach for when something there looks structurally odd.
- **Docs CI is build-only.** `.github/workflows/docs.yml` builds the Jekyll site and deploys successful main builds through Pages Actions. It does not run `rake test`, Python helpers or native CLI/model checks. Check the actual configured provider requirements before shipping; a successful site build does not prove those deferred checks passed.
- **`git filter-repo` removes `origin` and rewrites more refs in its default full-rewrite mode.** `/helm:normalize` uses explicit `--refs` partial mode instead: it preserves remote configuration, all existing tags, and excluded refs. Do not restore unbounded filtering or reconstruct a remote from only its URL; verify it stayed unchanged.
